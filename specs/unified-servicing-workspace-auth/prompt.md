- **[78098]** Unified authenticated workspace entry
- **[78138]** As a Service Agent, I want to search by a single-record identifier so that I can retrieve the correct customer and account summary quickly (5 pts)
  Acceptance:
1. Supported single-record identifier searches return the matching customer and account summary within 2 seconds under expected load
2. Search results display data that corresponds to the searched identifier and do not mix customer or account summaries from unrelated records
3. The lookup flow masks or restricts protected fields according to role-based authorization and applicable customer privacy obligations
4. User can search by a single-record identifier so that I can retrieve the correct customer and account summary quickly through the documented happy-path flow
5. System validates required inputs before completing "search by a single-record identifier so that I can retrieve the correct customer and account summary quickly"
- **[78147]** As an Account Management Specialist, I want the customer summary and related account summary shown together in the workspace so that I can review servicing context without switching to legacy tools (3 pts)
  Acceptance:
1. When an Account Management Specialist opens a valid authorized record in the workspace, the page displays a customer summary section and a related account summary section together within the same web view.
2. When the specialist performs a new valid single-record search, both summary sections update to the newly resolved record context and no values from the previously displayed record remain visible as current data.
3. If the searched identifier is valid but no related account summary is available, the workspace still shows the customer summary and presents a controlled no-account-available state instead of a broken or blank page.
4. Any payment-related account data shown in the summary excludes prohibited PCI-sensitive values, and any partially displayable values are masked according to configured display rules.
5. If summary retrieval fails because of an upstream or processing error, the workspace shows a controlled error state for the summary area and does not expose stack traces, internal field names, or restricted payload details.
- **[78155]** As an Account Management Specialist, I want to open Mimir and other protected modules from the workspace with shared identity context so that I can complete related servicing tasks efficiently (3 pts)
  Acceptance:
1. Authorized navigation from the workspace to Mimir or another protected module reuses the authenticated identity context without prompting for a second login
2. The receiving module enforces its own role-based authorization and does not inherit permissions beyond the specialist's approved scope
3. Module launch failures or denied transitions display controlled messages and do not expose protected routing or security details
4. User can open Mimir and other protected modules from the workspace with shared identity context so that I can complete related servicing tasks efficiently through the documented happy-path flow
5. System validates required inputs before completing "open Mimir and other protected modules from the workspace with shared identity context so that I can complete related servicing tasks efficiently"
- **[78164]** As a Service Agent, I want the unified workspace to preserve my session and page context while I move across supported CM and AM screens so that I can complete servicing work with less interruption (2 pts)
  Acceptance:
1. When an authenticated Service Agent navigates between supported CM and AM routes within the active session window, the workspace keeps the application session valid without forcing a new login prompt.
2. When the agent moves from one supported CM or AM screen to another that supports carried context, the current customer or account identifier is preserved and the destination screen loads the same record context automatically.
3. If the destination screen does not allow inherited customer or account context, the workspace does not display stale record data and instead opens the screen in its default protected state.
4. When the application detects session expiration during navigation or protected API activity, protected content is blocked, the agent is routed to the secure reauthentication path, and the previous page stops exposing customer or account data.
5. Refreshing the browser on a supported protected route during a still-valid session restores the same route and permitted customer or account context without requiring the agent to repeat the prior search.
- **[78171]** As a Compliance Role, I want all protected customer and account access events recorded in an immutable audit trail so that the organization can support security and privacy reviews (5 pts)
  Acceptance:
1. Each successful or failed access to protected customer or account summary data creates an audit record containing event type, user identity, timestamp, target record identifier, module name, and outcome without requiring manual action by the user.
2. Administrative session events for sign-in success, sign-in failure, token validation failure, and protected access denial are captured as separate audit events with enough detail to distinguish the event reason during review.
3. Once written, an audit event cannot be updated or deleted through the application path used by CM and AM services, and any attempt to overwrite an existing event identifier is rejected.
4. Audit records are stored with a consistent schema and can be exported in a reviewable format that preserves original field values, event ordering metadata, and outcome information.
5. If audit persistence is temporarily unavailable when a protected access event occurs, the application records the failure in operational logs/metrics and does not falsely report the access event as successfully audited.
- **[78180]** As a System Administrator, I want the web workspace rollout controlled with versioned APIs and feature flags so that supported legacy CM and AM functions can transition safely (3 pts)
  Acceptance:
1. When a supported CM or AM workspace function is marked disabled in rollout configuration, the function is not displayed in workspace navigation or action menus for authenticated users.
2. When a supported CM or AM workspace function is enabled in rollout configuration, the workspace exposes that function without requiring any manual user-role update.
3. Protected backend endpoints used by the workspace are available through explicit versioned routes, and requests to the configured version return the expected contract for the enabled function.
4. If a user attempts to access a disabled function by direct route or API call, the system returns a controlled denial response and does not execute the protected operation.
5. Functions identified as out of scope for legacy replacement are excluded from workspace discovery responses and are not presented as available web capabilities.
- **[78188]** As a System Administrator, I want monitoring for workspace availability and lookup performance so that the unified web workspace meets operational resilience targets (3 pts)
  Acceptance:
1. Monitoring captures metrics for authentication success and failure, workspace availability, and protected API health for supported CM and AM web functions.
2. The system records response-time telemetry for single-record customer summary and account summary retrieval requests with enough detail to evaluate the 2-second service target.
3. An operational alert is generated when lookup performance for customer or account summary retrieval breaches the configured 2-second threshold under expected load conditions.
4. Monitoring data distinguishes failure, degraded response, and recovery status for workspace components rather than reporting only a generic up or down state.
5. Telemetry emitted for workspace monitoring excludes sensitive customer and account content while preserving identifiers needed for correlation and troubleshooting.
- **[78114]** As a Service Agent, I want to sign in to the unified CM and AM web workspace with enterprise SSO so that I can start customer and account servicing from one secure entry point (3 pts)
  Acceptance:
1. When an unauthenticated user opens the unified workspace URL, the application redirects the browser to the configured WorkOS enterprise SSO login flow before any protected CM or AM content is displayed.
2. After a valid WorkOS authentication callback for an authorized internal identity, the application creates a session and routes the user into the unified CM and AM workspace without requiring a separate legacy desktop login.
3. If the WorkOS callback is missing required validation data, is invalid, or the authentication attempt fails, the application shows a sign-in failure state and does not create a workspace session.
4. If the authenticated identity is not authorized for internal servicing functions, the application blocks workspace entry with an access-denied response and does not render customer or account workspace content.
5. All sign-in requests and callbacks are processed over encrypted transport, and the established session uses secure handling appropriate for protected customer and account servicing access.
- **[78122]** As a System Administrator, I want JWT-backed application sessions validated on protected workspace requests so that only authenticated identities can use CM and AM functions (3 pts)
  Acceptance:
1. Each protected workspace request validates the JWT session and rejects expired, malformed, or tampered tokens before CM or AM data is returned
2. Session validation derives application access from the authenticated enterprise identity and applies least-privilege role checks to protected modules
3. Session failures are logged with identity, timestamp, and reason without exposing sensitive token contents in audit records
4. User can I want JWT-backed application sessions validated on protected workspace requests so that only authenticated identities can use CM and AM functions through the documented happy-path flow
5. System validates required inputs before completing "I want JWT-backed application sessions validated on protected workspace requests so that only authenticated identities can use CM and AM functions"
- **[78131]** As an Account Management Specialist, I want the workspace home page to show only the CM, AM, and related modules I am allowed to use so that I can enter servicing functions quickly and securely (2 pts)
  Acceptance:
1. When an authenticated Account Management Specialist loads the workspace home page, only tiles and navigation entries for authorized CM, AM, and explicitly permitted related modules are rendered.
2. If the authorization response contains no entitlement for a protected module, that module is absent from the visible home page layout and cannot be launched from the landing page.
3. If the authorization service returns an error or timeout during home page load, the page shows a non-technical access retrieval error state and does not display protected module tiles by default.
4. Module tile labels, navigation labels, and destination links shown on the home page match the approved unified workspace terminology for the authorized modules across supported browsers.
5. Selecting an authorized module tile routes the user to the corresponding protected module entry point within the authenticated workspace session without exposing unauthorized navigation options.
