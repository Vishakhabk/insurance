## User Stories

- **[91918]** Edited As a Bug Management User, I want to record a bug for the DemoIntern project so that defects are captured with consistent and traceable information (5 pts)
  Acceptance:
1. Submitting a valid POST /api/projects/{projectId}/bugs request for the DemoIntern project creates exactly one bug_records entry and returns a response containing the generated bugId, projectId, reporter, and creationTimestamp. 2. The created DemoIntern bug persists the baseline fields title, description, status, priority, severity, and reporter using only values that exist in the configured status, priority, and severity lookup tables. 3. If title, description, status, priority, severity, or reporter is missing, blank, or invalid, the system rejects the request, returns field-level validation errors for the failing fields, and does not create a bug_records row. 4. If the request projectId does not map to the DemoIntern project scope, the system blocks creation, returns a project-scope error response, and does not generate a bug identifier. 5. Before persistence, the system sanitizes title and description content containing markup or script input, stores the sanitized values, and allows the created bug to be retrieved through GET /api/projects/{projectId}/bugs/{bugId} over authenticated TLS-protected access.
