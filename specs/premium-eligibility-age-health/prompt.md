## User Stories

- **[101717]** As an Underwriter, I want to capture applicant age and health information so that premium eligibility decisioning uses complete underwriting data (3 pts)
  Acceptance:
1. The underwriting data capture flow requires applicant age and the configured health fields before the record can be marked ready for premium eligibility decisioning.
2. The system validates age as a realistic numeric value based on date of birth or entered age and displays field-level errors for missing, conflicting, or out-of-range values.
3. The system prevents submission when required health responses are blank, use unsupported values, or contradict related answers in the same application record.
4. Only authorized underwriting roles can view or update health information, and each view or update action is recorded with application identifier, actor, action type, and timestamp.
5. A successfully saved record persists applicant age and health inputs so they are retrievable by the underwriting workflow without allowing unapproved derived factors to be entered manually.
6. The underwriting evaluation screen loads the applicant's calculated age, captured health information, application identifier, and current data completeness status before an eligibility decision can be submitted.
7. If required underwriting inputs are missing, inconsistent, or fail validation, the system blocks submission of the eligibility outcome and displays field-specific validation messages identifying the exact issue.
8. When the Underwriter submits a valid assessment, the system stores the eligibility outcome together with applicantId, underwritingAssessmentId, evaluated age and health data snapshot, decision timestamp, and decision source.
9. The system restricts risk evaluation and eligibility submission to authenticated users with underwriting permissions and returns an authorization error for users without the required role.
10. Each completed underwriting decision is retrievable for review with its associated applicant record, assessment details, and trace information showing when and from which source the decision was produced.
- **[101730]** As an Underwriting System, I want to apply approved age and health rules to premium eligibility so that decisions are consistent and compliant (5 pts)
  Acceptance:
1. System calculates premium eligibility decisions using validated customer age and health information as permitted decision inputs
2. System applies only approved underwriting and eligibility rules and blocks decision execution when required inputs or permitted rule references are not available
3. System stores decision outcome, input values, rule version, timestamp, and actor or system source for audit traceability and regulatory review
4. User can apply approved age and health rules to premium eligibility so that decisions are consistent and compliant through the documented happy-path flow
5. System validates required inputs before completing "apply approved age and health rules to premium eligibility so that decisions are consistent and compliant"
- **[101733]** As a Product Administrator, I want to manage premium eligibility rules for age and health so that underwriting updates can be made without code changes (5 pts)
  Acceptance:
1. Authorized users with Product Administrator access can create, edit, validate, activate, deactivate, and view premium eligibility rules that use age and health criteria without direct database changes or code deployment.
2. When a rule set is published, the system assigns a unique version identifier, preserves the prior version unchanged, and makes the active version available for subsequent premium eligibility decisions.
3. The system prevents publication of a rule set when required fields are missing, age ranges overlap within the same product context, or referenced health conditions/operators are invalid, and it displays field-specific validation errors.
4. Every rule create, update, publish, and deactivate action records immutable audit details including actor, timestamp, action type, before/after values, and rule version.
5. Each premium eligibility decision executed after publication stores a trace record that includes the evaluated applicant age input, health data inputs used by the rule, the matched rule identifier, and the exact published version applied.
